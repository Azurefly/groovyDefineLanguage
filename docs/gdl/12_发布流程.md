# GDL 发布流程

## 版本号规则

遵循 [语义化版本](https://semver.org/lang/zh-CN/)：`主版本.次版本.修订号`

- 主版本：不兼容的 API 变更
- 次版本：向下兼容的功能新增
- 修订号：向下兼容的问题修复

## 发布检查清单

### 1. 代码冻结前
- [ ] 全量测试通过：`mvn -o verify` 确认 `BUILD SUCCESS`，0 failures/errors
- [ ] 真实场景测试通过（`gdl-ontology-test/run.sh syntax` + `knife`）
- [ ] CHANGELOG.md 的 `[Unreleased]` 小节已写完

### 2. 打版本
```bash
# 1. 去掉 -SNAPSHOT
# pom.xml: <version>1.0.0-SNAPSHOT</version> -> <version>1.0.0</version>
# 2. CHANGELOG: ## [Unreleased] -> ## [1.0.0] - YYYY-MM-DD，并补上版本说明
# 3. 提交
git commit -m "Release 1.0.0"
# 4. 打 tag
git tag -a v1.0.0 -m "GDL 1.0.0 首个正式版本"
git push origin main v1.0.0
```

### 3. 发布后
```bash
# 5. 切回开发版本
# pom.xml: <version>1.0.0</version> -> <version>1.0.1-SNAPSHOT</version>
# CHANGELOG.md 顶部新增 ## [Unreleased]
git commit -m "切回 1.0.1-SNAPSHOT 开发版本"
git push origin main
```

### 4. Maven Central 发布（可选）

如需发布到 Maven Central：
1. 在 Sonatype 申请 `com.pl` GroupId
2. 配置 GPG 签名：`~/.m2/settings.xml` 加 server 配置
3. pom.xml 加 `maven-gpg-plugin` + `nexus-staging-maven-plugin`
4. `mvn clean deploy -P release`

> 当前状态：已完成 1-3 步（本地 tag + GitHub）；第 4 步待 Sonatype 账号。

## 回滚

```bash
git tag -d v1.0.0
git push origin :refs/tags/v1.0.0
```
